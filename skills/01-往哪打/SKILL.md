# 往哪打：点位与优先级

## 这个技能解决什么

"这批人今天该去哪"，多数团队靠记忆和习惯。结果是三种浪费：好点位没人去、差点位反复去、新点位没人知道。

这个技能只做一件事：让点位成为一张能看、能排、能追责的表。

## 输入

- 点位清单：名称、经纬度、类型、负责人、当前状态。字段见仓库 `docs/数据与边界.md`。
- 业务口径：一个"好点位"由什么决定（人流量、客群匹配、竞品密度、距离）。
- 今天能派出去的人数和时间。

没有点位清单，先别做图。图是清单的可视化，清单不存在时做出来的图是装饰。

## 步骤

1. **定状态词表，四个，不多不少。** `未接触` `已接触` `有进展` `重点跟进`。多了记不住，记不住就填错；少了分不出优先级。
2. **给每个点位挂负责人。** 没有负责人的点位等于不存在，一周之后没人记得谁去过。
3. **算优先级，别拍优先级。** 排序依据写死三条，例如：距上次到访天数降序、状态为未接触优先、路上时间不超过 N 分钟。规则写在表头或 README 里，谁看都能复算。
4. **画出来。** 跑 `python3 scripts/build_map.py --points 你的表.csv --out map.html`。颜色是状态，形状是类型。底图自己接，仓库故意没接。
5. **每天派活时只看两条**：今天谁去哪几个点位，昨天那几个点位带回了什么。其余维度不要在早会上讲。

## 判据

- 随机指一个点位，能不能一句话说出：谁负责、上次什么时候去的、现在什么状态。答不上，这张表没建立起来。
- 指派是否可复算：换一个人按同样的规则排，能不能排出同一个顺序。排不出来，说明规则还在脑子里。

## 什么时候不该用

- 点位数量少于 10 个：纸笔或一张表就够，做系统是浪费。
- 人员还在流动、点位每周大变：先稳定业务，图会变成每周重画一次的成本。
- 团队连"去过没去过"都不愿意填：先解决风气。工具会让不愿意记的人多一个不填的理由。

## 常见走偏

- 把图画得很漂亮，但没有状态和负责人：这是宣传品，不是管理工具。
- 点位定得太多。城市级点位一次性全导进去，人会挑容易的去。先 50 个以内，跑两周再加。
- 用点位数量当成绩。点位多少不代表业务进展，去过且带回来东西的才算。
